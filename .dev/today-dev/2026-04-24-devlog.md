## 1. 학습한 내용 및 활동 결과

### 1-1. 개발 환경 구성

Vite + React 19 기반의 프론트엔드 프로젝트 초기 환경을 구성하였다. 빌드 도구로 Vite를 선택한 이유는 HMR(Hot Module Replacement) 속도가 webpack 대비 현저히 빠르고, ES Module 기반의 네이티브 번들링으로 개발 서버 구동 속도를 최소화할 수 있기 때문이다. 서버 없이 LocalStorage만으로 데이터를 관리하는 구조를 채택하여 MVP 개발 속도를 높이고 배포 복잡도를 낮추는 전략을 적용하였다.

### 1-2. 공통 UI 컴포넌트 설계 및 구현

재사용 가능한 공통 컴포넌트 6종을 설계하고 구현하였다. CSS 변수(Custom Properties) 기반 디자인 토큰을 도입하여 색상, 간격, 폰트 크기 등 시각적 일관성을 코드 수준에서 강제하는 구조를 만들었다. 컴포넌트 계층은 `Layout > Container > Card` 순으로 감싸며, `Button`, `Input`, `Header`는 독립적으로 조합 가능하도록 설계하였다.

> **구현 컴포넌트 목록**: Button, Card, Input, Header, Layout, Container

#### 소스코드 캡처 ①: `useLocalStorage.js` — LocalStorage와 React State 동기화 훅

```javascript
// src/hooks/useLocalStorage.js
function useLocalStorage(key, initialValue) {
  const [storedValue, setStoredValue] = useState(() => {
    try {
      const item = window.localStorage.getItem(key);
      if (item) {
        return JSON.parse(item);
      }
      return initialValue;
    } catch (error) {
      console.error(`LocalStorage 접근 오류 (${key}):`, error);
      return initialValue;
    }
  });

  const setValue = (value) => {
    try {
      // 함수가 전달된 경우 실행 (prev => next 패턴 지원)
      const valueToStore = value instanceof Function ? value(storedValue) : value;
      setStoredValue(valueToStore);
      window.localStorage.setItem(key, JSON.stringify(valueToStore));
    } catch (error) {
      console.error(`LocalStorage 저장 오류 (${key}):`, error);
    }
  };

  return [storedValue, setValue];
}
```

> **학습 포인트**: `useState`의 lazy initializer(함수 형태 초기값)를 활용하여 컴포넌트 마운트 시 단 한 번만 LocalStorage를 읽도록 최적화하였다. 또한 `setValue`에서 함수 인자를 허용함으로써 `setMatches((prev) => [...prev, newItem])` 패턴이 안전하게 동작하도록 설계하였다.

#### 소스코드 캡처 ②: `useMatchData.js` — 경기 및 참여자 CRUD 훅 (핵심 로직)

```javascript
// src/hooks/useMatchData.js
function useMatchData() {
  const [matches, setMatches] = useLocalStorage('epl_matches', []);

  // 새 경기 생성 — timestamp 기반 고유 ID 자동 부여
  const createMatch = useCallback(
    (matchData) => {
      const newMatch = {
        id: `match_${Date.now()}`,
        createdAt: new Date().toISOString(),
        status: 'recruiting',
        participants: [],
        ...matchData,
      };
      setMatches((prev) => [newMatch, ...prev]);
      return newMatch;
    },
    [setMatches]
  );

  // 참여자 추가 — 경기 배열 내 불변 업데이트
  const addParticipant = useCallback(
    (matchId, participantData) => {
      const participant = {
        id: `p_${Date.now()}`,
        joinedAt: new Date().toISOString(),
        ...participantData,
      };
      setMatches((prev) =>
        prev.map((match) =>
          match.id === matchId
            ? { ...match, participants: [...match.participants, participant] }
            : match
        )
      );
      return participant;
    },
    [setMatches]
  );

  return { matches, createMatch, addParticipant, /* ... */ };
}
```

> **학습 포인트**: 배열 내 중첩 객체를 불변(immutable)하게 업데이트하기 위해 `map` + spread 패턴을 사용하였다. `useCallback`으로 함수 참조를 메모이제이션하여 하위 컴포넌트의 불필요한 리렌더링을 방지하였다.

#### 소스코드 캡처 ③: `csvExport.js` — 한글 BOM 처리 CSV 내보내기 유틸

```javascript
// src/utils/csvExport.js

// CSV 값 이스케이프 (쉼표·줄바꿈·큰따옴표 포함 시 큰따옴표로 감싸기)
const escapeCSV = (value) => {
  if (value === null || value === undefined) return '';
  const stringValue = String(value);
  if (stringValue.includes(',') || stringValue.includes('\n') || stringValue.includes('"')) {
    return `"${stringValue.replace(/"/g, '""')}"`;
  }
  return stringValue;
};

// BOM 추가로 Excel 한글 깨짐 방지
export const downloadCSV = (csvContent, filename = 'export.csv') => {
  const BOM = '﻿';
  const blob = new Blob([BOM + csvContent], { type: 'text/csv;charset=utf-8;' });
  const link = document.createElement('a');
  const url = URL.createObjectURL(blob);
  link.setAttribute('href', url);
  link.setAttribute('download', filename);
  document.body.appendChild(link);
  link.click();
  document.body.removeChild(link);
  URL.revokeObjectURL(url);  // 메모리 누수 방지
};
```

> **학습 포인트**: Windows Excel에서 UTF-8 CSV 파일의 한글이 깨지는 문제는 BOM(`﻿`)을 파일 앞에 삽입하여 해결할 수 있다. `URL.revokeObjectURL`로 Blob URL을 즉시 해제하여 메모리 누수를 방지하는 패턴을 적용하였다.

## 2. 고찰 및 추후 개발 계획

### 2-1. 고찰

이번 Phase 1 구현을 통해 컴포넌트 간 데이터 흐름과 LocalStorage 동기화의 구조적 패턴을 확립하였다. 특히 `useLocalStorage → useMatchData → Page` 계층 구조는 데이터 접근 책임을 명확히 분리해 가독성을 높였다. 반면, 참여자 추가 후 `currentMatch`를 `matches` 배열에서 다시 조회하는 패턴은 LocalStorage 쓰기와 React 상태 갱신 사이의 타이밍 차이로 인해 동기화 불안정 가능성이 존재하며, 이는 `useEffect` 의존성 정리 또는 직접 반환값 활용으로 개선할 필요가 있다. 또한 `handleDeleteMatch`가 `deleteMatch`를 실제 호출하지 않아 LocalStorage 데이터가 남는 미완성 이슈가 남아있어 다음 세션에서 즉시 처리할 예정이다.

## 3. 이슈 발생 및 처리

### 이슈 #1 — [해결] Vite import-analysis 경로 오류

| 항목 | 내용 |
|------|------|
| **발생 위치** | `src/pages/MatchPage.jsx` |
| **증상** | Vite 빌드 시 `Failed to resolve import "./components/..."` 오류 발생 |
| **상태** | ✅ 해결 완료 |

**원인 분석 및 해결 과정**

파일을 `src/` 루트에서 `src/pages/` 하위로 이동한 이후, import 경로를 갱신하지 않아 발생한 오류이다. Vite는 ES Module 사양을 엄격하게 준수하므로 상대 경로가 실제 파일 위치를 정확히 가리켜야 한다. `src/pages/MatchPage.jsx`는 `src/components/`, `src/hooks/` 폴더와 한 단계 위 디렉토리(부모)를 공유하므로 `./components` → `../components`, `./hooks` → `../hooks`로 경로를 수정하는 것이 올바른 처리이다. 이를 통해 모듈 해석이 정상화되어 빌드가 성공적으로 완료되었다. 향후 파일 이동 시에는 IDE의 자동 import 경로 갱신 기능을 활용하거나 절대 경로 alias(`@/components`)를 `vite.config.js`에 설정하는 것이 근본적인 예방책이 될 수 있다.

```javascript
// 수정 전 (오류)
import { Layout, MatchForm } from './components';
import { useMatchData } from './hooks';

// 수정 후 (정상)
import { Layout, MatchForm } from '../components';
import { useMatchData } from '../hooks';
```

### 이슈 #2 — [해결] `useForm` 잘못된 import 경로로 인한 빌드 오류

| 항목 | 내용 |
|------|------|
| **발생 위치** | `src/components/MatchForm.jsx`, `src/components/ParticipantForm.jsx` |
| **증상** | `useForm is not exported by src/utils/index.js` 빌드 에러 발생 |
| **상태** | ✅ 해결 완료 |

**원인 분석 및 해결 과정**

`useForm`은 `src/hooks/` 디렉토리에 정의된 커스텀 훅임에도 불구하고 컴포넌트에서 `../utils`로 잘못 import하여 발생한 오류이다. React 프로젝트에서 커스텀 훅(use- 접두사)은 반드시 `hooks/` 디렉토리에 위치해야 한다는 컨벤션을 지키지 않은 것이 직접 원인이 아니라, 경로 입력 실수가 원인이었다. `src/utils/index.js`에는 `csvExport`, `validators`, `constants`만 re-export되므로 `useForm`이 존재하지 않아 번들러가 오류를 발생시킨 것이다. `../utils` → `../hooks`로 경로를 수정한 후 빌드가 정상화되었다.

```javascript
// 수정 전 (오류)
import { useForm } from '../utils';

// 수정 후 (정상)
import { useForm } from '../hooks';
```

> 프로젝트 규모가 커질수록 각 디렉토리의 `index.js`에서 명확하게 re-export를 관리하고, 각 디렉토리의 역할(utils = 순수 함수, hooks = React 훅)을 엄격히 구분하는 것이 유사 오류를 예방하는 핵심 방법이다.

### 이슈 #3 — [미해결] `handleDeleteMatch` 실제 데이터 삭제 미연결

| 항목 | 내용 |
|------|------|
| **발생 위치** | `src/pages/MatchPage.jsx` — `handleDeleteMatch` 함수 |
| **증상** | 경기 삭제 버튼 클릭 시 화면 상태(`currentMatch`)만 초기화되고, LocalStorage의 경기 데이터는 그대로 남음 |
| **상태** | ⚠️ 미해결 — 다음 세션에서 처리 예정 |

**원인 분석**

`useMatchData` 훅에서 `deleteMatch` 함수를 정상적으로 export하고 있음에도 `MatchPage`의 구조 분해 할당에서 `deleteMatch`를 포함하지 않았고, `handleDeleteMatch` 내부에서도 호출하지 않았다. 현재는 `setCurrentMatch(null)`로 화면에서만 경기를 숨기는 동작을 하고 있어, 페이지 새로고침 시 해당 경기가 다시 목록에 나타나는 문제가 발생한다.

**조치 예정**

```javascript
// 수정 예정 코드
const { matches, createMatch, addParticipant, removeParticipant, updateMatch, deleteMatch } = useMatchData();

const handleDeleteMatch = () => {
  if (!window.confirm('경기를 삭제하시겠습니까?')) return;
  deleteMatch(currentMatch.id);         // LocalStorage에서도 제거
  setCurrentMatch(null);
  window.history.pushState(null, '', '/');
};
```
